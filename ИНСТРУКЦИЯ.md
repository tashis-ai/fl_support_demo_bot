# RAG-ассистент онлайн-школы

Telegram-бот отвечает на вопросы о курсах, сертификации и программах школы по базе знаний. Ответ строится через RAG: поиск фрагментов в ChromaDB + генерация через ProxyAPI.

Сайт школы: https://example.com

---

## Как запустить

```bash
cd "D:\WBCODE\PEcf09 logs"
venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Перед запуском:

1. Заполните `.env` (образец — `env.example`).
2. По умолчанию стартует Telegram (`APP_MODE=3`).
3. Прокси для Telegram — только если нужен: задайте `TELEGRAM_PROXY` в `.env`. На сервере обычно оставляют пустым.

Остановка: `Ctrl+C`. После правок кода бота нужно перезапустить.

---

## Что делает система

1. Пользователь пишет вопрос в Telegram (или в консоли).
2. Проверяется кеш (`cache.json`). Если такой вопрос уже был — ответ возвращается сразу.
3. Иначе выполняется векторный поиск по базе знаний (ChromaDB).
4. Найденные фрагменты + вопрос отправляются в LLM через ProxyAPI.
5. Ответ сохраняется в кеш и пишется в лог (`logs.db`).

Прокси Telegram **не** используется для ProxyAPI: туда запросы идут напрямую.

## База знаний

Список документов в коде указывать не нужно. При **пустой** ChromaDB программа сама читает все `.txt` из папки `docs/`. Имя файла без расширения становится названием документа.

Сейчас в `docs/`:

| Файл | Содержание | Источник |
| --- | --- | --- |
| `progs.txt` | Курсы для специалистов, 5 модулей, цены и расписание 2026, допуски, экзамен |
| `sert.txt` | Сертификация IBP I–III, MBP, CBA-S, экзамен, поддержание квалификации |
| `rk.txt` | Курсы и семинары для родителей, FAQ, цены |

Документы подгружаются **только если коллекция пустая**. После добавления или правки `.txt`:

1. Остановите бота.
2. Удалите папку `chroma_db` (и при необходимости `cache.json`, чтобы не отдавать старые ответы).
3. Запустите `python main.py` снова.

## Настройки `.env`

### Обязательные для ответов

| Переменная | Смысл |
| --- | --- |
| `PROXYAPI_API_KEY` | Ключ [ProxyAPI](https://proxyapi.ru/) |
| `PROXYAPI_BASE_URL` | `https://api.proxyapi.ru/openai/v1` |
| `PROXYAPI_MODEL` | Модель генерации, сейчас `gpt-4o-mini` |

Клиент OpenAI оставлен как библиотека: ProxyAPI совместим с OpenAI API. Прямых запросов на `api.openai.com` нет.

### Telegram

| Переменная | Смысл |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_PROXY` | Опционально. Пусто = напрямую; иначе URL прокси, например `http://127.0.0.1:7890` |
| `APP_MODE` | Режим запуска |

`APP_MODE`:

- `3` / `telegram` / `bot` — Telegram (значение по умолчанию)
- `1` / `interactive` / `console` — консоль
- `2` / `demo` — демонстрационные вопросы

### Опционально

| Переменная | Факт в коде |
| --- | --- |
| `EMBEDDING_MODEL` | Читается, по умолчанию `text-embedding-3-small` |
| `CHROMA_PERSIST_DIR` | В `.env` есть, в коде путь зашит: `./chroma_db` |
| `CACHE_FILE` | В `.env` есть, в коде путь зашит: `cache.json` |
| `LOGS_DB_PATH` | В `.env` есть, в коде путь зашит: `logs.db` |
| `TEMPERATURE` | В `.env` есть, в коде зашито `0.7` |

## Telegram-бот

Приветствие: «Добро пожаловать в RAG-ассистента онлайн-школы!»

Команды:

- `/start` — приветствие
- `/help` — справка и примеры вопросов
- `/stats` — число документов, кеш, логи
- `/logs` — CSV со всеми логами взаимодействий

Обычное текстовое сообщение обрабатывается как вопрос к базе знаний. Длинные ответы режутся на части (лимит Telegram ~4096 символов). Если ответ взят из кеша, бот пишет «ответ из кеша».

---

## Логирование

Включено всегда, отдельного флага нет. Каждый вопрос и ответ пишется в `logs.db`:

- время, вопрос, ответ
- источник (`console` / `telegram`)
- `user_id` и `username` (для Telegram)
- был ли ответ из кеша
- время ответа в мс

Как посмотреть:

- в боте: `/logs` и `/stats`
- в консоли (режим 1): команды `logs` и `stats`

## Прокси для Telegram

Параметр `TELEGRAM_PROXY` в `.env` — **опциональный**:

- не задан или пустой → бот ходит в Telegram напрямую (так и нужно на большинстве VPS);
- задан URL → используется только для Telegram API (ProxyAPI по-прежнему напрямую).

Пример для локальной работы в РФ:

```env
TELEGRAM_PROXY=http://127.0.0.1:7890
```

На сервере строку лучше закомментировать или оставить пустой.

## Типичные проблемы

**База не видит новые файлы из `docs/`**  
Коллекция уже не пустая. Удалите `chroma_db` и перезапустите.

**Бот не стартует, ConnectError**  
С сервера Telegram недоступен, либо локально нужен `TELEGRAM_PROXY`. На VPS чаще всего прокси не нужен.

**Нет `PROXYAPI_API_KEY`**  
Ответы и эмбеддинги не создадутся. Проверьте `.env`.

**Старый текст приветствия**  
Бот не перезапущен после правок `telegram_bot.py`.

**Ответ про старую тему (Python, RAG)**  
Либо в `docs/` ещё лежат старые файлы, либо не очищена `chroma_db` / `cache.json`.

## Деплой через Docker

Полная инструкция: раздел «Деплой на сервер» в `README.md`.

```bash
git clone https://github.com/tashis-ai/fl_support_demo_bot.git
cd fl_support_demo_bot
cp env.example .env   # PROXYAPI_API_KEY, TELEGRAM_BOT_TOKEN
mkdir -p data/chroma_db
echo '{}' > data/cache.json && touch data/logs.db
docker compose up -d --build
docker compose logs -f rag-school-bot
```

| Тема | Совет |
| --- | --- |
| Порты | Long polling — наружу ничего не открываем |
| Прокси | Опционально через `TELEGRAM_PROXY`; на VPS обычно пусто |
| Секреты | `.env` только на сервере, не в git |
